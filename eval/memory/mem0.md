# mem0 (`--memory mem0`)

**System.** mem0 (Chhikara et al., 2025, arXiv:2504.19413), official repository mem0ai/mem0, installed from PyPI as `mem0ai==2.1.0` and imported, not re-implemented. The adapter was written against upstream commit `a39a802`. What runs is the installed package, whose per-file sha256 are recorded in `requirements-mem0.txt`. Importing `mem0.memory.main` runs `setup_config()`, which mkdir -p's `$MEM0_DIR` and writes `$MEM0_DIR/config.json` (a generated installation id); the adapter sets `MEM0_DIR` unconditionally to `<tempdir>/revoke_mem0` at import, so that write never lands in the operator's `~/.mem0`. It is the only file the backend writes; it reads no dataset file.

**What it stores.** Short natural-language facts the backbone extracted from departed sessions, embedded with the harness's local embedder (hashed bag-of-words fallback here) in an in-process Qdrant collection scoped by `user_id` = the world. Metadata carries `session` (the runner's session index) and `kind` ("session" or "action"). The agent's own action at each probe is stored verbatim through mem0's `infer=False` raw path as `you did: chose <action> -- <rationale>`, tagged `role=assistant` / `actor_id=you`, with no LLM call.

**When it writes.** One `Memory.add` per departed session, through one of two pipelines (cfg `pipeline`). `additive` (default) is what `pip install mem0ai==2.1.0` runs: one LLM call carrying `ADDITIVE_EXTRACTION_PROMPT` plus existing memories, the last `last_k_messages` rows of mem0's message table and the new session; ADD-only, it never rewrites or deletes. `reconcile` is the paper's two-phase pipeline (extract facts, then ADD/UPDATE/DELETE/NONE against the nearest memories), ported from mem0ai 1.0.11, which is the last release that shipped it; it makes **two** calls per session, or **one** when extraction returns no facts (the `if new_retrieved_facts` guard — visible in the smoke run below, where 31 observes cost 31 calls because the canned reply parses to nothing). 1.0.11 is neither installed nor vendored, so the port's deviation list rests on the author's notes; `requirements-mem0.txt` gives the command to close that gap.

**Cost (measured, not estimated).** Offline replay of real `data/long100` episode-1 blocks (433 sessions, ~3.3k chars each) with a fake backbone, counting prompt chars at `RevokeLLM.generate_response` (table below). `additive` costs ~2.7x `reconcile` despite half the calls, because its static system prompt is 33,653 chars re-sent on every observe. "Last 10 messages" does not re-send ten whole transcripts, although observe hands mem0 a session block as one message: mem0 truncates each past message to `PAST_MESSAGE_TRUNCATION_LIMIT = 300`, so that section costs ~3.1k chars. The cfg `last_k_messages` (default 10 = upstream) bounds it anyway, but `last_k=2` saves only ~2.5k chars/session (~6%): the static prompt is the cost and no knob bounds it. `additive`'s per-session cost is near-flat in store size; `reconcile`'s second call grows with it.

| pipeline | calls/session | chars/session | ~tok/session | ~tok/episode (433) | ~tok for 50 episodes |
|---|---|---|---|---|---|
| `additive` (default) | 1 | 40,193 (system 33,653 \| last-k 3,121 \| new session 3,174 \| existing ~130) | 10.0k | 4.4M | 218M |
| `reconcile` | 2 | 14,928 (extract 7,344 + update 7,584) | 3.7k | 1.6M | 81M |

**How it reads.** At a probe, `Memory.search(task, filters={"user_id"}, top_k=12, threshold=0.1)`, rendered one line per memory, `[session N]` / `[you]` / `[earlier session]`, as many as fit the recall budget. `order` defaults to mem0's score ranking. Chronology is **not** available from mem0: `created_at` is the wall-clock time of the write, not the in-world session time (in an offline replay every memory lands in the same second), so the only ordering signal is the session index in the metadata — which is what `order="session"` sorts on. Sweep `order` as a condition; a memory system that cannot tell a rule from its later revocation by time is exactly what REVOKE is measuring.

**Deliberate deviations from library defaults.** (1) `top_k=12`, upstream's `Memory.search` default is 20; 12 matches the other retrieval backends (MemOS also uses 12) so they are compared at equal retrieval depth. Twelve short facts render to ~1-2k chars against a `--recall-budget 4000` (16k chars), so mem0 is retrieval-bound, not budget-bound — report `mem_chars` vs the budget; `top_k` 12/20/40 is the natural sensitivity sweep. (2) `action_task_chars=0`: the probe's text is not spliced into the action memory. REVOKE probes within a world are near-identical in wording, so an action memory carrying the task text is by construction the nearest neighbour of every later probe and evicts the extracted session rules from `top_k` — an adapter artifact that biases the backbone toward repeating its own earlier, possibly since-revoked, choice. A development run measured 45/95 recall lines `[you]` (47%) at 240 chars vs 23/95 (24%) at 0; an offline re-check with a synthetic extractor reproduced the direction more starkly (100% vs 0.3% of 900 rendered lines). The task text is verbatim in the prompt at the moment of recall, so nothing is lost; 240 stays available as an ablation. (3) `threshold=0.1` is mem0's own default and is left alone: the threshold gates the raw cosine before hybrid combination, and with the hashed fallback embedder 96.5% of long100 candidates score >= 0.1 (a 200-candidate re-check gave 97.0%), so it excludes almost nothing. (4) `bm25=False` and spaCy disarmed — see `requirements-mem0.txt`.

**Reading a run.** `stats()` reports `degraded` = more than 20% of mem0's own LLM calls came back empty or unparsable. Any episode with `degraded: true`, any `llm_empty > 0`, any `errors > 0` or a `last_error` must be discarded and re-run, never graded: a backbone outage is otherwise indistinguishable from "the model extracted nothing" (both give `memories: 0`, `extraction_empty: N`), so a 402/429 storm during a sweep would yield a full set of traces that read as "mem0 remembered nothing". Three consecutive `Memory.search` failures now raise and fail the episode rather than silently returning empty recall for every remaining probe, and a `top_k`/`threshold` cfg mem0 would reject raises at construction instead of mid-episode. **Smoke test:** `python3 scripts/smoke_memory.py --memory mem0 --limit 12 --window 600` and the same with `--cfg '{"pipeline":"reconcile"}'`: both print `OK` (12/12 tasks acted, 31 observes, 31 memory LLM calls, recall non-empty on 5 of 12 probes, 253-650 chars). The fake backbone returns a canned prose paragraph, so extraction never parses: `extraction_empty: 31`, `memories: 0`, `points: 12` (the 12 action memories) and `degraded: True` are the expected shape of a smoke run, not a defect.
